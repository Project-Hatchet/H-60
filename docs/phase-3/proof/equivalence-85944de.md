## 2. Config-value proof — `tools/config_dump` + `compare_dumps.py`

Riverman captured the Phase 1 config-dump harness in game on each build (labels `scons-85944de`, `hemtt-85944de-fix`): the full spawn matrix, `vtx_H60_base`, and every sound/function root the pack contributes.

```
compared 653045 values: 562473 identical, 90504 equivalent after normalisation, 68 DIFFERENT
only in A: 0   only in B: 0
```

- **562,473 byte-identical.**
- **90,504 equivalent after normalisation** — the three serialisation differences the comparer was built for: CfgConvert stores unquoted arithmetic as strings (`"160/256"`) where HEMTT stores the number; Arma's preprocessor parenthesises substituted macro arguments (`((3+0.2)-0.1)`) where HEMTT does not; `ARR_n` expansions are spaced differently inside SQF code strings. The engine resolves all three identically.
- **68 DIFFERENT, all one class, HEMTT correct:** text on the CCFS credits/menu page that passed through a macro argument. CfgConvert's preprocessor dropped the commas inside the quoted text (`"We as a team have decided…"`); HEMTT keeps them (`"We, as a team, have decided…"`). The HEMTT build restores the authors' punctuation. No other value differs.

## 3. The regression this proof caught, and its fix

The first HEMTT capture (`hemtt-85944de`) showed **114 wrong values** and Riverman's smoke run showed the symptom at once: white lines crossing the whole PFD after start-up.

**Cause.** The PFD pitch ladder and roll indicator, the NVGHUD roll bar and trim ball, and the BFT and Hellfire icons place their points with trigonometric expressions such as `(sin 30 * (0.013))`, generated by six macros (`ANGLEX`/`ANGLEY`/`BFT_ANGLEX`/`BFT_ANGLEY` in `uh60_mfd` and `uh60_weapons` `mfdDefines.hpp`, `ANGLEX`/`ANGLEY` in `uh60_anvishud/config/NVGHUD/defines.hpp`) plus one composed site (`HELLFIREANGLE` in `hellfireMFD.hpp`). CfgConvert stores such expressions as **strings** and the engine evaluates them at load with SQF rules: `sin` takes degrees and binds before `*`. HEMTT evaluated them at **build time** with its own calculator: radians, and `cos 0 * (-0.22)` parsed as `cos(0 * -0.22)`. Every affected point became a garbage coordinate.

**Fix** (`phase3/wp3-followups`): the six macros emit `QUOTE(...)`, with bare `_EXPR` variants for the composed site, so both toolchains ship the exact text CfgConvert always shipped and the engine keeps evaluating it. Proven by: scons builds of the three addons derapifying identical before and after; the rebuilt HEMTT config carrying the points as strings; manifest compare back to 0 unexpected; the second capture above.

**Law for the tree:** any config expression that uses an SQF function (`sin`, `cos`, `tan`, `sqrt`, …) must be quoted. A grep confirms no other unquoted site exists. This is also worth an upstream issue on HEMTT (build-time evaluation of SQF-function math uses radians and the wrong unary precedence).
